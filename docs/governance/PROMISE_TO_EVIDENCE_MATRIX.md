## Review rule

Every externally visible product claim must map to one row. If no row and reproducible evidence exist, add the gap to the backlog or qualify/remove the claim; do not treat a roadmap item, code presence, AI output or submitted prose as proof.

Those remain owned by their existing readiness, golden-flow and controlled-metrics stories.

### IL-7.1-IL-7.2 post-submission control

The pure `readiness.v1` result remains explicitly unpersisted. `IL-7.2` wraps that exact value in an immutable persisted ReleaseAssessment, derives every authority/freshness input from storage and proves historical `STALE` without rewriting the assessed status. At the `IL-7.2` checkpoint this could be cited as persistence/restart/staleness evidence, but not as browser readiness, Release Passport, release approval, deployment authority or the complete `BLOCKED → READY → STALE` golden demo. `IL-7.3` later added the internal Passport projection and `IL-7.4` added bounded API/UI; the remaining integration proof and release/demo boundaries belong to `IL-7.5`-`IL-8.6`.

`IL-7.3` creates one unsigned immutable Passport from one persisted assessment and proves exact projection/digest/history/stale-association behavior. At that checkpoint it could be cited as internal Passport implementation evidence, but not as a signed attestation, browser workflow, export, release approval, deployment authorization or completed golden demo. `IL-7.4` now closes only the bounded API/UI portion; `IL-7.5`-`IL-8.6` retain the remaining proof/demo boundaries.

### IL-7.5 post-submission control

Generated `EV-READINESS` and `EV-PASSPORT` evidence closes the controlled cross-layer proof: zero negative fixture cases returned `READY`; assessment and Passport state survives restart; Project/Mission scope does not leak; canonical corruption fails closed; the browser consumes server-owned state; and no provider/network call occurs. These results may be cited as deterministic local implementation evidence. They are not production validation, evidence truth, a signed attestation, release approval, deployment authorization or the Phase-8 judge-facing golden workflow.
